# 中文技術文件寫作

目標：寫出像資深工程師寫的繁體中文（台灣）技術文件。**平實**、**具體**、**短句**。

## 流程

**寫新文件：**

1. 先想清楚讀者是誰，讀完要能做成什麼事。一句話說不清，先問使用者。
2. 按下面的「句子」「語氣」「段落與結構」「排版」寫。
3. 自我檢查：拿「AI 腔清單」逐條對照全文，命中的全部改掉。
4. 跑 `autocorrect --fix <檔案>`，修空格和標點。命令不存在就跳過，改為按「排版」手動檢查。
5. 手動檢查 autocorrect 管不到的：引號、刪節號、破折號。

**修改已有文件：**

1. 通讀全文，再動手。
2. 使用者只要意見：按「原句 → 改後 → 原因」列出問題，不改檔案。
3. 否則直接改，然後做上面的第 3～5 步。最後用兩三句話說明改了哪幾類問題。

每一步都做完才算完成。第 3 步的標準是：清單每一條都對照過，全文沒有命中。

## 句子

- 用逗號隔開的每一截，盡量在 20 字以內。超過 30 字就拆開。整句不超過 100 字。
- 一句只說一個意思。多用簡單句和並列句，把長修飾語拆出去。
  - 差：那個昨天生病的人沒有參加會議。
  - 好：他昨天生病了，沒有參加會議。
- 用肯定句，不用雙重否定。
  - 差：請確認沒有接通裝置的電源。 → 好：請確認裝置的電源已關閉。
  - 差：沒有刪除權限的使用者，不能刪除此檔案。 → 好：使用者必須有刪除權限，才能刪除此檔案。
- 用主動語態，少用「被」。
  - 差：假如此軟體尚未被安裝 → 好：假如還沒安裝這個軟體
- 動詞直接用，不套「進行」「做出」。
  - 差：對設定檔進行修改 → 好：修改設定檔
- 「這」「其」「該」只指一個明確的對象。可能有歧義就把名詞重複一遍。
- 名詞前的修飾語不超過兩層，多了就拆成兩句。
- 用現代中文常用詞，不用文言、生造詞。
  - 差：這是唯二的方法。 → 好：只有這兩種方法。
- 分清「的、地、得」：開心的笑容、開心地笑、笑得開心。
- 用台灣用語，不用中國用語。

## 語氣

- 像給同事講清楚一件事：口語化可以，網路流行語不用。
- 稱呼讀者用「你」，稱呼專案方用「我們」。
- 用陳述語氣，句末用句號。
- 用事實代替形容詞：給出數字、命令、檔名、錯誤訊息原文。
  - 差：效能得到了大幅提升。
  - 好：p99 延遲從 120 ms 降到 40 ms。
- 確定的事直接說。不確定就說清楚哪裡不確定、怎麼驗證。

## 段落與結構

- 每段第一句說這段的重點，後面的句子為它服務。一段一個主題。
- 一段最好不超過 4 行，最多 7 行。
- 標題用二級、三級為主：
  - 一級標題下直接接二級，不跳級。
  - 同級標題只有一個時，去掉這層標題。
  - 下級標題不重複上級標題的名字。
  - 需要四級標題時，改用 `**（1）xxx**` 或清單。
  - 標題末尾不加句號、逗號、冒號。
- 清單只放真正並列、可以單獨掃讀的條目。有因果、轉折關係的內容，寫成段落。
- 粗體只給讀者必須注意的警告或關鍵字，一個螢幕最多一兩處。
- 引用別人的內容或圖片，註明出處。

## 排版

每篇都要守的規則：

- 中文與英文、數字之間加一個半形空格：`在 Linux 上安裝 5 個套件`。
- 中文句子用全形標點：`，。：；？（）`。整句是英文時用半形標點。
- 英文、數字後面緊跟全形標點時，中間不加空格：`他用的是 MacBook Air。`
- 引號用 `「」`，引號裡再套引號用 `『』`。不用 `“ ”`。
- 並列的詞用頓號 `、` 隔開，最後一項用「和」連接：`Google、台積電和聯發科`。
- 刪節號寫成 `……`，不寫 `...` 或 `。。。`，也不和「等」連用。
- 數字一律用半形。

數字（千分位、單位、範圍、倍數）、括號、冒號、連接號、英文縮寫的細則，見 [references/typography.md](references/typography.md)。文件裡出現這些內容時讀它。

寫一整套產品手冊或文件網站、需要規劃目錄和檔名時，讀 [references/manual-structure.md](references/manual-structure.md)。

## AI 腔清單

自我檢查時逐條對照。左邊是要找的寫法，右邊是改法。

| 找這種寫法 | 改成 |
|---|---|
| 開場套話：「隨著……的發展」「在當今……」「值得注意的是」「需要指出的是」「讓我們來看看」「接下來我們將介紹」 | 刪掉，第一句直接說內容 |
| 結尾套話：「總的來說」「綜上所述」「總而言之」，或重複前文的總結段 | 刪掉。確實需要結尾，只寫新資訊，比如下一步做什麼 |
| 客套話：「希望對你有幫助」「如有問題歡迎交流」 | 刪掉 |
| 對比句式：「不是 A，而是 B」「與其說 A，不如說 B」 | 直接說 B |
| 遞進句式：「不僅……而且/更……」 | 拆成兩個陳述句 |
| 硬湊三個：三個排比形容詞、每組都是三項的清單 | 有幾項寫幾項 |
| 設問自答：「關鍵是什麼？答案很簡單：」「原因很簡單：」 | 直接給結論 |
| 宣傳腔形容詞：強大、靈活、無縫、全面、極致、優雅、輕鬆、一站式 | 換成具體事實，沒有事實就刪 |
| 行話：優化、打造、賦能、落地、痛點、亮點、生態系、解決方案、擁抱、驅動、洞察 | 換成白話。程式碼或業務裡的正式名稱（如「Kubernetes 生態系」）保留 |
| 破折號 `——` 用來插入解釋 | 改用逗號、冒號、括號，或拆成兩句。全文最多一兩處 |
| 翻譯腔：「進行 + 動詞」「透過……的方式」「作為一個……」、一句裡多個「的」 | 直接用動詞，拆開長修飾語 |
| 過度含糊：「在某種程度上」「在一定情況下可能會」 | 確定就直接說；不確定就說清條件 |
| 驚嘆號、emoji 標題或清單符號 | 句號，純文字標題 |
| 每段都粗體、一兩句話也拆成清單、小標題比段落還密 | 按「段落與結構」重排 |
